Generated by `rads/config/create_splits.py` (seed 42). Split file: `rads/config/picek_heldout_split_v2.csv`.

Bugs addressed: B3 (wrong source ids, per-class uniqueness, duplicate `video_id`) and B13 (hardcoded absolute paths).

## 1. Source-id extraction

The previous implementation dropped the last underscore-separated segment:

```python
parts = base.split('_')
return '_'.join(parts[:-1]) if len(parts) > 1 else base.split('.')[0]
```

The duplicates arise because uniqueness was enforced separately within each class, so the same basename appears once with label 1 and once with label 0. `rads/evaluation/evaluator.py` keys checkpoint recovery on `video_id`, so a resumed run would silently skip the second occurrence of each duplicated id.

## 3. Pairing policy

Each selected source contributes exactly one pair: the positive clip and the negative clip that share the same basename, as `rads/config/p02_test_split.csv` does with its `clip_role` values `positive_accident` and `negative_pre_accident`. In the PICEK sorted dataset every negative clip has a positive clip of the same basename, so pair correspondence is unambiguous: 1,530 of the 2,027 positive clips have a negative counterpart.

Rationale:

- MVP.md section 13 and MASTER_SPEC.md section 14 require all clips from one source video to stay within a single split. Pairing satisfies that requirement: both clips of a source land in this one held-out set and nowhere else.
- The MVP pipeline is rule-based and has no trained parameters, so there is nothing for a within-split source repeat to leak into.
- Pairing makes every negative a hard negative from the same camera, scene and lighting as its positive. That is the hard-negative category MVP.md section 12 calls for, and it is the condition under which the baseline's 83.8% false-positive rate is actually informative.

Rejected alternative: disjoint sources per class, that is, positives from one set of sources and negatives from an entirely different set. This was rejected because it reintroduces appearance-based separability between the accident and normal classes, letting scene identity rather than motion evidence drive the decision.

## 6. Schema

Columns: `video_id`, `source_video_id`, `binary_label`, `clip_role`, `processed_path`, `split_in_distribution`.

`rads/evaluation/evaluator.py` reads `video_id`, `binary_label` and `processed_path`. `split_in_distribution` is carried for consistency with the P02 split; `source_video_id` and `clip_role` are carried for the integrity checks and for failure analysis.

`video_id` is `picek_pos_<stem>` or `picek_neg_<stem>`, the prefix convention of `p02_test_split.csv`, which makes ids unique across the two classes and safe for checkpoint recovery.

`processed_path` is repository-root relative and begins with `Datasets/processed/`. The evaluator's path block joins a non-absolute path that does not start with `processed` onto the repository root, so `Datasets/processed/...` resolves correctly, whereas a bare `processed/...` prefix would take the other branch and be joined onto `<root>/Datasets` a second time. All 500 paths were resolved through a replica of that block and all 500 exist on disk.

## 7. P02 source overlap

`rads/config/p02_test_split.csv` covers 37 sources. Four of them also appear in this held-out split:

```
0puo8kJOlmU  CnsDyfXdf8s  QB42gU5X634  aF2Hbp8C23A
```

These were not removed. The claim this split supports is "held out from threshold tuning", not "held out from P02". No P02 source was used to tune any threshold, so the overlap does not contaminate the tuning-exclusion claim; it is recorded here as a transparency note. When the two result sets are compared, four of the 250 held-out sources are shared with the P02 test set and the two sets are not statistically independent at the source level.

For reference, 81 of the 250 selected sources also appear in the previous `picek_500_split.csv`. That file was never used for tuning either, so this too is a note rather than a contamination.

## 8. What the leakage claim covers

Supported:

- No clip in this split comes from a source used to tune reasoning or severity thresholds during Phases 1-7.
- Every source appears in exactly one split, this one, with both of its clips. Source-video separation as defined in MVP.md section 13 and MASTER_SPEC.md section 14 holds.
- Class balance is exact by construction, 250 and 250, rather than by sampling.
- `video_id` is unique, so a resumed evaluation run processes every row.

Not supported:

- This is not a held-out set with respect to P02. Four sources overlap and are listed above.
- It is not a training/validation holdout in the machine-learning sense. The MVP pipeline has no trained parameters; the only fitted quantities are the hand-set thresholds, and the exclusion list above is what "held out" refers to.
- The positive and negative clips of a pair come from the same source video, by design. Any metric that assumes independent samples across the 500 rows is overstating its effective sample size; the effective unit is the 250 pairs.
